# Speckit 工作流说明

**创建日期**: 2025-01-27  
**上下文**: 敌人 AI 系统实施后的下一步行动

## Speckit 工作流概述

Speckit 工作流主要用于**实施前的规划阶段**：

1. **`/speckit.clarify`** - 澄清规范中的模糊点
2. **`/speckit.plan`** - 生成实现计划（plan.md, research.md, data-model.md 等）
3. **`/speckit.tasks`** - 生成任务列表（tasks.md）
4. **`/speckit.implement`** - 执行实施（按 tasks.md 执行任务）
5. **`/speckit.analyze`** - 分析一致性（实施后验证）

根据 `tasks.md`，所有任务都标记为 `[X]`（已完成）：

### 实际情况

但是，这些系统目前只是**占位符**，没有实际移动逻辑：
- `chase_system`: 只检查状态，不更新 Transform
- `patrol_system`: 只计算目标，不更新 Transform
- `return_to_patrol_system`: 只检查状态，不更新 Transform

### 为什么会出现这种情况？

1. **任务描述不够具体**: 任务说"更新移动目标"，但没有明确要求"实际移动敌人"
2. **实施时的简化**: 为了快速验证核心逻辑（状态机、感知系统），先实现了占位符
3. **后续改进**: 移动系统集成是实施后发现的改进点

## 下一步的选择

**理由**:
- 这是实施后的改进，不是原始规范的一部分
- 移动系统集成是技术实现细节，不需要重新规划
- 快速见效，立即看到敌人移动

**操作**:
- 直接实现 `patrol_system`、`chase_system`、`return_to_patrol_system` 的实际移动逻辑

**优点**:
- 快速
- 不需要重新规划
- 立即看到效果

### 选项 2：更新 tasks.md 添加新任务

**理由**:
- 保持任务列表的完整性
- 可以跟踪改进进度

**操作**:
```markdown
## Phase 7: Movement Integration (Post-Implementation)

- [ ] T070 实现 patrol_system 的实际移动逻辑（直接更新 Transform）
- [ ] T071 实现 chase_system 的实际移动逻辑（直接更新 Transform）
- [ ] T072 实现 return_to_patrol_system 的实际移动逻辑（直接更新 Transform）
```

**优点**:
- 保持任务列表完整
- 可以跟踪进度

**缺点**:
- 需要手动更新 tasks.md
- 可能过度文档化

### 选项 3：创建新的子规范

**理由**:
- 如果移动系统集成涉及复杂决策（如物理引擎选择）
- 如果需要多个步骤和测试

**操作**:
```bash
# 创建新的子规范
/speckit.specify 004-enemy-ai-movement-integration
```

**优点**:
- 完整的规划流程
- 适合复杂改进

**缺点**:
- 对于简单的移动集成可能过度
- 需要更多时间

## 何时使用 Speckit 工作流

### 应该使用 Speckit 的情况：

1. **新功能规划**: 需要完整的功能规范
2. **复杂决策**: 需要研究和技术决策
3. **多步骤实施**: 需要详细的任务分解
4. **团队协作**: 需要清晰的规划和文档

### 不需要 Speckit 的情况：

1. **实施后的改进**: 如移动系统集成
2. **Bug 修复**: 直接修复即可
3. **简单优化**: 如性能优化、代码重构
4. **技术债务**: 如代码清理、重构

**不需要**: 重新运行 `/speckit.tasks` 或创建新规范，因为这是实施后的技术改进，不是新功能。

**如果选择更新 tasks.md**: 可以手动添加 Phase 7 来跟踪改进进度，但不是必需的。
